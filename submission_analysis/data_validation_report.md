## Replay from the response cache

## Notes that affect interpretation

- `runtime_seconds` is measured per problem and per k-condition. Because all k-conditions share the same seeds, a later k-condition reads the responses drawn by an earlier one from the cache, so its runtime does not measure generation time. The gpt-4.1-mini run was also interrupted during k = 100 and resumed; on resumption k = 1 and k = 10 were read entirely from the cache. Runtimes should not be used as a measure of compute.
- The model ids are the aliases sent with each request (`gpt-4.1-mini`, `gpt-4o-mini`). The exact model snapshot returned by the API was not recorded and is unavailable.
- Problems without a valid final prediction are counted as wrong; their confidence and entropy are recorded as 0.
